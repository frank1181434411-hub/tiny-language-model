## 2026-10-25 实际结果

准备完成，下载、筛选、编码和校验合计 **204.67 秒（约 3 分 25 秒）**。
正文下载 66 MiB，新数据目录与缓存合计 143,300,929 字节，约 137 MiB；没有测量峰值内存。

| --- | ---: | ---: | --- |
| train | 50000 | 12,046,442 | 下一轮训练，保留原 6133 篇 |
| val | 323 | 69,576 | 与旧实验完全相同的验证输入 |
| heldout | 1000 | 256,961 | 最终独立检查，暂未评估模型 |

16 个训练块得到 75003 篇完整且正文精确唯一的候选，两个验证块得到 2221 篇候选。
在填满训练集所检查的候选中，排除 44 篇词规范化后训练重复、2 篇与评估集重叠的故事；
这两个过滤计数只覆盖实际遍历的候选前缀，不代表整个候选池或官方全库。

所有原训练故事保留；三份最终数据之间无词规范化后的完全重复。
扩充过程的近似重复过滤采用下述固定规则，不声称已经消除所有语义相似内容。
train/heldout 均通过逐分片完整解码、EOS 数与原生文件加载校验；历史目录所有文件哈希不变。
下载块哈希与数据统计见[精简清单](tinystories-expanded-manifest.json)，完整逐故事哈希留在本地 manifest.json。

新增 5 项定向测试通过，覆盖 UTF-8 块边界、完整故事要求、词面近似匹配、保护集合完整性和拒绝整文件响应。
Ruff、格式和 diff 空白检查通过；未重跑全量模型测试。
准备时对照配置的模型及 training 字段与旧 15000 步配置完全一致，训练结果另见上面的实验链接。

## 来源和下载预算

使用作者发布的 [roneneldan/TinyStories](https://huggingface.co/datasets/roneneldan/TinyStories)，固定 revision：
`f54c09fd23315a6f9c86f9dc80f725de7d8f9c64`。
取原始 TinyStories-train.txt 和 TinyStories-valid.txt，不混用 GPT4-only V2。
官方数据卡标注为 GPT-3.5/GPT-4 生成的合成故事，许可为 CDLA-Sharing-1.0；
数据来源说明保存在下载缓存的 README.source.md，原始语料不随项目推送。

完整训练文件为 1,924,281,556 字节。本次不下载全库：

- 训练文件划为 16 个等宽字节区间，每区间用 seed=42 取一个 4 MiB 块。
- 官方验证文件划为两个区间，用 seed=43 各取 1 MiB。
- 正文下载预算固定为 66 MiB，另有很小的数据卡请求；服务器不遵守 Range 请求时直接报错，不退回整文件下载。
- 每块只保留两个完整 EOS 分隔符之间的故事，丢掉首尾片段后才做严格 UTF-8 解码。
- 统一换行为 LF，去掉故事外围空白，保留内部段落。候选按 seed 与内容的 SHA-256 排序。

这是分层随机字节块抽样，**不是全库故事的均匀随机抽样**；长故事更容易跨块边界被舍弃。
清单保存各块的偏移、长度和 SHA-256；仅下载了部分源文件，因此不声称已校验完整上游文件哈希。
固定 revision、Python 环境与缓存块可复现本次选择。

## 划分与泄漏检查

训练集目标为 **50000 篇**，包括保留的全部 **6133 篇原训练故事**和 **43867 篇新增故事**。
原验证集 **323 篇**及 tokenizer.json、val.bin、val.bin.json、val.txt 逐字节复制。
tokenizer 保持原有 2048 词表，不重新训练，便于与旧模型比较。

另从官方验证文件选出 **1000 篇 heldout**，用于最终独立检查，不用于调学习率、选 checkpoint 或逐步追踪效果。
先排除它与全部历史训练/验证故事的重复，再用历史验证集及 heldout 过滤新增训练候选。
准备阶段未在该数据上计算模型指标；后续仅在两轮各自按原验证集选定 checkpoint 后进行最终留出评价。

重复规则为：忽略大小写和标点后的词序列完全相同，或词 5-gram 集合 Jaccard 相似度至少 0.8。
历史训练集也先按该规则审计；若与保留评估数据冲突则报错，不能悄悄改掉原基线。
训练集内部做词规范化后的完全重复去重；没有对全部训练故事做两两近似去重。
这种词面规则不能保证消除语义重复或所有数据泄漏。

## 编码与产物

输出位于 `data/tinystories-expanded-50k-v1/`：

- train-shards/、heldout-shards/：每个文件最多 500 篇完整故事，每篇恰有一个 EOS，保留内部换行。
- train.bin、heldout.bin 及各自元信息：调用项目已有多文件预处理接口，按文件顺序编码并写盘。
- 原样复制的 tokenizer.json、val.txt、val.bin 和 val.bin.json。
- manifest.json：来源、抽样块、历史文件哈希、过滤计数、故事哈希、token 数及验证结果；所有检查成功后才生成。

分片避免一次编码整份 5 万篇文本。每个分片完整解码回原文本，校验 EOS 数、文件哈希、词表绑定和 ID 范围。
所有分片都在 EOS 后换行处结束；不把段落行当作独立故事。现有训练窗口仍可跨故事边界，EOS 不会建立 attention 隔离。
下载缓存位于 `downloads/tinystories-ranges-v1/`；缓存、语料和二进制产物由 Git 忽略。

## 复现与训练预算

Git Bash 中执行，输出目录必须不存在；本机已完成时不要重复运行同名输出：

```bash
cd /d/Python/tiny-language-model
PYTHON=/d/Python/.venvs/tiny-language-model/Scripts/python.exe
"$PYTHON" scripts/expand_tinystories.py --output-dir data/tinystories-expanded-50k-v1
```

失败时保留部分输出供排查；重跑使用新的 --output-dir，可复用下载缓存。
不增加依赖、不修改模型算法，不会启动训练。

准备好的配置沿用 2 层、128 维、上下文 128、batch=8、seed=42、15000 步和相同学习率计划。
必须从头训练，不能用旧 checkpoint 跨数据集续训；项目输入绑定会拒绝这种不一致。
未来只计划一轮约 20 分钟的 CPU 对照，30 分钟时重新评估是否继续；这是执行预算，不是配置内置的自动超时机制。
完成对照后先总结，不自动增加步数或扩大到全量语料。
